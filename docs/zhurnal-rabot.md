## 17 сентября 2026 (с Mac)

### Прогнан полный набор тестов после Фазы 0 — нашёлся и закрыт баг

`git pull` подтянул Фазу 0 с ноутбука на Windows. Локально поднят Postgres, `pnpm test`
прогнан впервые после этих правок (в журнале ниже это было записано как несделанное).

Нашёлся реальный баг, не просто устаревшие тесты: возврат (`apps/api/src/routes/orders.ts`)
искал открытую смену условием `opened_by = ctx.userId`. Работало, пока возврат делал тот же
кассир, что открыл смену. Фаза 0 отдала право на возврат владельцу и управляющему — а у
владельца `ctx.branchId` вообще пуст, он не привязан к филиалу. Возврат падал 409 «смена не
открыта», из-за этого расходились суммы в отчётах (6 тестов красных).

Исправлено: возврат теперь ищет открытую смену по `branch_id` **заказа**, а не по
исполнителю или его текущему филиалу. Два прогона `pnpm test` подряд — 86 тестов, всё зелёное.

### Как проверить на Windows

```
git pull
pnpm install
pnpm test
```

Ожидание: как и раньше, все наборы проходят, включая `reports.test.ts`.

## 17 сентября 2026

### Фаза 0 — безопасность (в работе, тесты не прогнаны)

Начаты три согласованные задачи. Код написан, **интеграционные тесты не запускались**:
на рабочем ноутбуке PostgreSQL требует пароль, которого у меня нет. Юнит-тесты ядра
тарификации прогнаны — 25 из 25 проходят, расчёт цены не затронут.

| Файл | Что изменено |
|---|---|
| `db/migrations/012_pin_lockout.sql` | Новая таблица `pin_lockouts` и функции `pin_lock_seconds`, `pin_note_failure`, `pin_note_success`. Счётчик промахов по PIN хранится в базе: перезапуск сервера не обнуляет защиту, а при нескольких копиях API счётчик общий. После 5 промахов — пауза 60 секунд |
| `apps/api/src/routes/auth.ts` | Вход по PIN сначала проверяет паузу, при блокировке отвечает `429` и говорит, сколько ждать. Промах засчитывается только после опознания устройства — иначе счётчик можно было бы накрутить чужой кассе. Верный PIN снимает счётчик |
| `apps/api/src/auth.ts` | Сервер не стартует в продакшене с секретом подписи по умолчанию (`dev-secret-change-me`). В разработке поведение прежнее |
| `apps/api/src/routes/orders.ts` | Возврат требует права `payment.refund` — это владелец и управляющий. Кассир получает `403`. Раньше проверки не было вообще: возврат мог оформить кто угодно, включая бухгалтера |
| `apps/pos/src/Receipts.tsx` | Кассиру кнопка «Возврат» не показывается — сервер ему всё равно откажет |
| `apps/api/test/reports.test.ts` | Два существующих возврата в тестах переведены на токен владельца: по новой логике кассиру они запрещены |

**Что по этой фазе ещё не сделано:** тест на блокировку после пяти промахов, тест «кассир
получает 403 на возврат», подсказка кассиру вместо скрытой кнопки, прогон полного набора
тестов, обновление README про переменную `JWT_SECRET`.

Асет прошёл все 34 вопроса. Ответы лежат в базе опросника, разбор — в `docs/gotovnost.html`.

  один, снята с ближайших работ и оставлена настройкой на будущее.
- **Считать по времени входа**, а не посегментно. Наш посегментный расчёт остаётся —
  добавляем переключатель на услуге.
- **Филиалов три и больше.** Добавить филиал из кабинета сейчас нельзя совсем.
- **Выручку относить на смену прихода**, а не оплаты.
- Минимального времени нет, праздничных цен нет, уборка между гостями не нужна, предоплату
  за бронь не берут, абонементы не продают, запись к сотруднику не нужна.
- Возврат — владелец и управляющий. На стойке только ноутбук: принтера чеков и ящика нет.
- **Оператор ОФД не выбран.** Хостинг — «решайте сами». Подписка — 7 000 и 12 000 ₸.

### Аудит облачного кабинета Paloma

Зашёл в `dashboard.paloma365.com` под демо-аккаунтом. Полный разбор — часть 2
в `docs/paloma-razbor.md`, 14 скриншотов в `docs/paloma/`. Главное:

- **Paloma для такой бани стоит 24 900 ₸ в месяц**, а не 12 600, как мы считали. Оплата
  помодульная и за каждое рабочее место: точка 1 800 + касса 3 600 × 2 + «Тарифы» 3 600 +
  «Склад» 3 600 + депозит, подарки, сертификат по 500 + «Калькуляции» 1 800 + УРВ 5 400.
  Тарификатор — отдельный платный модуль.
- **Тариф** = товар + интервал + цена + дата начала + список объектов + «специальные тарифы»
  (дни недели, время, интервал, цена). Ни включённых гостей, ни доплаты за гостя, ни
  минимального времени, ни округления, ни выбора «по входу / по сегментам» там нет.
- **Филиал** = торговая точка; переключателя филиала нет, разрез задаётся фильтром в отчётах.
- **Права** складываются из шести слоёв: тип доступа, роли, разрешённые интерфейсы кассы,
  список рабочих мест, просмотр по каждой точке, 33 галочки прав фронта — плюс пароли
  на действия. У демо-кассира не отмечено ничего, отсюда и отказы на кассе.
- **Смена** привязана к точке, рабочему месту и сотруднику; в кабинете не редактируется,
  но есть кнопка «Закрыть незакрытые».
- **Фискализации в кабинете нет вообще.** Онлайн-кассы (Webkassa, ReKassa, Nurkassa,
  KaspiKassa, Trinity, e-POS, QPos, GREEnKassa, UZKASSA) подключаются интеграцией
  на рабочее место без доплаты. У демо-точки не подключено ничего.
