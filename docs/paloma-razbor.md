## 2. Как Paloma устроена

- ✅ П Фронт — классическое Windows-приложение (Delphi) с локальной базой MariaDB. Все
  экраны одного фронта: вход по PIN → плитки интерфейсов «Кассир», «Официант», «Режим
  продаж», «Тарификаторы» ([01](paloma/01-glavnyj-ekran-interfejsy-sinhronizaciya.png)).
- ✅ П Внизу главного экрана «Данные получены / Данные отправлены» с отметками раз в
  несколько минут. Фронт постоянно синхронизируется с облаком.
- ✅ П «МЕНЮ» → «Синхронизация», «Настройки», «Поддержка» ([02](paloma/02-menyu-i-vhod-po-pin.png)).
- ✅ П Интерфейсы — это не разные программы, а наборы действий на одном плане столов:
  - **Тарификатор** — план столов + «Опции сессии» (запуск тарифа) + «Журнал»;
  - **Официант** — тот же план, счета и предоплата, без запуска тарифа и без журнала;
  - **Кассир** — список счетов, оплата, касса, смена, отчёты, опции (возврат и т.п.);
  - **Режим продаж** — быстрый чек с кнопкой «Оплата», стол необязателен.
- 📖 Д Бэк-офис («Личный кабинет») — облачный: справочники, тарифы, документы склада и
  денег, отчёты владельца, права.
- 💭 В Разделение «кто создаёт счёт» и «кто берёт деньги» заложено в самой модели: тарификатор
  и официант не видят кнопку оплаты, деньги — только у кассира.

**У нас:** касса и кабинет владельца; права — 4 роли в коде; интерфейс кассы один для всех.
**Решение: улучшить** — экран «Роли и доступ» строить на этой модели: не «роль», а
«набор действий на кассе» (запуск времени / счета без денег / деньги и смена / быстрая продажа).

## 3. Касса и тарификатор: посещение от стола до оплаты

### Сценарий, как он есть в Paloma

1. ✅ П Администратор открывает «Тарификаторы». Слева «Помещения» («Общий зал»), в центре
   плитки столов со статусом: «Свободен» / «Занят с 12:32 (СЧЕТ: №1)»
   ([10](paloma/10-tarifikator-svobodnyj-stol.png)).
2. ✅ П Клик по плитке ставит на ней галочку — можно выбрать несколько столов сразу.
3. ✅ П У свободного стола справа «Статус объекта»: «Продажа», «Опции сессии» → «Запустить
   тариф», «Добавить к счету», переключатель «Оплата сразу» / «Оплата после», поля «Час(а)» и
   «Минут(ы)», «Сумма:». В шапке галочка «Уведомление о закрытии сессии».
4. 📖 Д Час/мин больше нуля — плановая сессия (гость знает время, закрытие берёт весь план,
   даже при раннем уходе); 0/0 — свободная (таймер, сумма по факту). На сайте заявлен и
   третий тип — «на сумму». Продлить можно только плановую. При закрытии сессии может
   отключаться электропитание объекта (реле).
5. ✅ П «Запустить тариф» открывает счёт, уже привязанный к столу: клиент «Частное лицо»,
   «Гостей 1», «Сервис 0%», «Скидка 0%», «Стол 2», справа каталог товаров, снизу «+», «−»,
   «Кол-во», корзина, «Примечание», «...» (скидка, сервис, примечание к счёту)
   ([11](paloma/11-tarifikator-schet-posle-zapuska.png)). Кнопки оплаты в этом счёте нет.
6. ✅ П «Назад» сохраняет счёт на столе: плитка стала «Стол 2 (СЧЕТ: №2)». У занятого стола
   панель меняется на «Счета»: «Новый счет» (ещё один счёт на тот же стол), «Просмотреть
   счет», «Предоплата».
7. ✅ П Оплата — в «Кассире»: выбрать счёт в списке → «Оплата» или «Предоплата» → форма
   «Выберите вид оплаты и введите сумму от клиента»: цифры и быстрые суммы «+100 … +20000»,
   «К оплате», «Сдача», виды оплаты «Наличными», «Картой», «В долг», «Депозитом», «Смешанная
   оплата», «Другие виды...» ([35](paloma/35-forma-oplaty-predoplata.png)). В демо «В долг» и
   «Депозитом» серые — выключены.
8. ✅ П «Параметры» формы оплаты = «Параметры текущей сессии»: «Запрашивать ИИН»,
   «Запрашивать E-mail» ([36](paloma/36-parametry-sessii-iin-email.png)).
9. ✅ П «Опции» кассира → «Изменить вид оплаты», «Копия чека», «Разбить счет», «Перенос блюд»,
   «Разблокировать счет», «История счета» ([33](paloma/33-opcii-kassira.png)).

- ❓ Н Как считается сумма сессии по времени, переход через границу под-тарифа, продление,
  закрытие сессии, уведомление о конце времени, фискальный чек — в демо нет тарифа и товаров.
- ❓ Н «Запустить тариф» открыл пустой счёт, хотя в кабинете тариф привязан ко всем столам. Причина неизвестна: возможно, фронт не получил справочники при синхронизации.
- ✅ П Пустой счёт на 0 ₸ держит стол занятым и блокирует закрытие смены — ни предупреждения,
  ни автоудаления.

### Сравнение

| Что | Paloma | У нас | Решение |
|---|---|---|---|
| Выбор помещения | план столов, помещение → стол, мультивыбор | список помещений | оставить наше; мультивыбор — **добавить позже** (компании на несколько кабинок) |
| Старт посещения | «Запустить тариф» с планом часов/минут или свободно | приём гостя, визит с таймером от серверного времени | оставить наше |
| Плановая / свободная сессия | обе; плановая берёт весь план при раннем уходе | план минут + продления, расчёт по факту | **улучшить**: явный выбор «оплата за план / по факту» в настройке услуги |
| «Оплата сразу / после» | переключатель при старте | оплата в конце | **добавить позже** — предоплата при входе нужна общественным баням |
| Несколько счетов на стол | «Новый счет» у занятого стола | один визит — один заказ | не нужно для бань (компания делит счёт через «разбить», см. ниже) |
| Разбить счёт, перенос позиций | есть | нет | **добавить позже** |
| Изменить вид оплаты после оплаты | есть | нет (только возврат) | **добавить позже** с журналом действий |
| История действий по счёту | «История счета»: товар, действие, дата, сотрудник | аудит в базе, в кассе не показан | **улучшить**: показать историю в карточке визита |
| Прозрачный разбор суммы до оплаты | ❓ не видно в демо | посегментный расчёт есть, разбор на экране — Фаза 1 | оставить наше, Фаза 1 |
| Доплата за гостей | нет (гости в счёте, в тарифе нет) | нет | Фаза 1 — **добавить** |
| Виды оплаты | наличные, карта, в долг, депозит, смешанная, другие | наличные, карта, перевод, абонемент, смешанная | депозит — **добавить позже**; «в долг» — не нужно для бань |
| Быстрые суммы, сдача | есть | ❓ не сверял | **улучшить**, если нет |
| ИИН / e-mail покупателя | параметры при оплате | нет | **добавить** вместе с фискализацией |
| Пустой счёт блокирует смену | да, без подсказки | закрытие смены блокируют активные визиты | оставить наше, но **улучшить** подсказку: «какие визиты и где» |

## 4. Тарифы и цены по времени

- 📖 Д Тариф: «Наименование», «Начало действия тарифа» (дата — фронт сам переключится на
  новые цены), «Товар» (для отчётов), «Интервал (мин)», «Цена» за интервал, «Объект»
  (стол, кабинка, комната). «Под тарифы» без ограничения: дни недели, время с/по,
  интервал, цена.
- 📁 Ф Таблицы: `s_tarifs` (тариф), `t_tarifs` (строки: пн…вс, время с/по, интервал, цена),
  `t_object_tarif` (тариф ↔ стол), `t_order_object_tarif_link` (запущенный тариф: стол, счёт,
  начало, `dt_stop`). Полей «минимальная длительность», «льготные минуты», «округление»,
  «включено гостей», «доплата за гостя» нет.
- 📁 Ф «Временные цены» — отдельный механизм: `s_time_price` (дни, время, даты) +
  `t_time_price_items` (товар, цена, `categoryid`) + `t_time_price_ap` (торговые точки).
- 📖 Д **`categoryid` — категория товара.** Справочник «Категория» в Paloma — «позволяет
  создать категории и привязать к ним товары, для последующей аналитики». Это не категория
  гостя (взрослый/ребёнок) и не тип цены.
- 📖 Д «Временная скидка» — скидка по дням/часам, отдельно от цен.
- 📖 Д «Типы цен» — дополнительные цены товара; контрагенту можно назначить свой тип цен.
- ❓ Н Как фронт применяет временную цену и под-тарифы на реальном счёте.

| Что | Paloma | У нас | Решение |
|---|---|---|---|
| Цена зала по дням/времени | тариф + под-тарифы | `price_rules`: маска дней, время, даты, приоритет | оставить наше |
| Смена прайса с даты | «Начало действия тарифа» | `date_from/date_to` в правиле | оставить наше |
| Минимум, шаг, льготные минуты | не видно в схеме | есть | оставить наше — это наше преимущество |
| Посегментный расчёт через границу | ❓ | есть, покрыт тестами | оставить наше |
| Льготные категории гостей | **нет** | нет | Фаза 2 — **добавить** (не копия Paloma) |
| Цена за человека / входной билет | товар по временной цене | `per_person`, `entry` в схеме, но не реализованы | Фаза 2 — **довести** |
| Скидки по расписанию | «Временная скидка» | нет | **добавить позже** |
| Персональные цены клиента | «Типы цен» у контрагента | нет | не нужно для бань |

6. 📁 Ф У записи (`s_journal`) есть ссылка на счёт (`orderid`), но нет статуса, числа гостей

- ✅ П Бронь на «Стол 1» сохранилась, хотя на нём в этот момент был открыт счёт — занятость
  стола сейчас и бронь не сверяются.

- ✅ П Форма записи модальная: если она оказалась под другим окном, весь фронт выглядит

- ✅ П Повторное «Создать запись» открывает прежние значения формы, клик по ячейке их не

- ❓ Н Пересечение броней: вторая запись на тот же стол и время молча не сохранилась, но

- ❓ Н Редактирование, перенос, удаление, предоплата по брони, перевод брони в счёт при

| Что | Paloma | У нас | Решение |
|---|---|---|---|
| Сетка «столы × время» | есть | шахматка | оставить наше |
| Непересечение | ❓, контроля занятости «сейчас» нет | `EXCLUDE` в СУБД + буфер уборки | оставить наше — сильнее |
| Статусы брони | нет | booked / arrived / cancelled / no_show | оставить наше |
| Гости в брони | нет | `guests_count` | оставить наше |

| Отмена / неявка в кассе | ❓ | есть в API, нет кнопок в кассе | **улучшить** |

## 15. Тарифы: как устроено и как настроено здесь

- ✅ П Карточка тарифа ([50](paloma/50-kabinet-tarif.png)): «Название», «Дата начала»

- ✅ П Блок **«Объекты»** — «Выберите для каких объектов действует тариф»: чекбоксы
  Стол 1, Стол 2, Стол 3 (отмечены все три), «Выбрать все» / «Снять все».
- ✅ П Блок **«Специальные тарифы»** — правила: «Название», «Дни» (Пн…Вс), «Время начала»,
  «Время окончания», «Интервал (мин.)», «Цена». Настроено одно правило: все дни,
  00:00–23:59, 60 мин, 2000 ₸. В форме добавления правила полей ровно столько же.
- ✅ П **Чего в тарифе нет совсем:** включённых гостей, доплаты за гостя, минимального
  времени, округления, льготных минут, выбора «по времени входа / посегментно»,
  привязки к категории гостя.

1. ✅ П **Paloma продаётся помодульно, и это дороже, чем мы считали**
   ([60](paloma/60-kabinet-moduli.png), [61](paloma/61-kabinet-moduli-ceny.png)).

   рабочие места 3 600 ₸ × 2 + «Тарифы» 3 600 ₸ + «Склад» 3 600 ₸ + «Депозит» 500 ₸ +
   «Подарки» 500 ₸ + «Сертификат» 500 ₸ + «Калькуляции» 1 800 ₸ + «Учёт рабочего времени»
   5 400 ₸. Включено 11 модулей из 23. **Тарификатор — отдельный платный модуль.**
   В нашем документе по ценам фигурировали 12 600 ₸ — для бани с двумя кассами реальность вдвое дороже.
2. ✅ П **Оплата зависит от числа рабочих мест**, а не только филиалов: каждая касса 3 600 ₸/мес.
   Это прямо бьёт по нашей формулировке «касс сколько нужно».

4. ✅ П **Вместимость стола** — поле справочника (у нас `capacity` есть, в цене так же не участвует).
